\subsection{Cross-Sectional vs.\ Time-Series Signals}

A central finding is the sharp divergence between global Rank IC and actual backtest performance for JKP-containing models. JKP factors carry the same value for all stocks within a given month; they encode \textit{market-level} information (business cycle, risk premia). An XGBoost model trained on these features learns to predict which months are ``good'' or ``bad'' on average --- market timing. Evaluated globally (Spearman across all stock-month observations), this inflates Rank IC because correct market-direction calls apply to all stocks simultaneously.

However, in a long-short portfolio construction, returns are measured as long minus short \textit{within} the same month. A constant prediction within any month produces a random stock ordering, collapsing to zero expected return before costs and negative net returns after. This explains why JKP-only yields undefined monthly Rank IC and $-4.5\%$ net annualised return.

FinBERT sentiment, in contrast, varies \textit{across firms} within the same month --- providing genuine cross-sectional discrimination between firms that just delivered strong versus weak earnings communications.

\subsection{The Combination Paradox}

Adding JKP features to FinBERT reduces out-of-sample net performance despite improving global Rank IC. Two mechanisms are at play:

\begin{enumerate}[noitemsep]
    \item \textbf{Signal crowding}: XGBoost allocates split budget to high-gain JKP features that carry time-series information. These splits are ``useful'' in the training set but do not improve --- and actively harm --- cross-sectional stock ranking in the test set.
    \item \textbf{Cost drag}: JKP-driven portfolios have 91\% monthly turnover vs.\ 58\% for FinBERT-only, generating $\approx 3\%$ additional annual transaction costs.
\end{enumerate}

The feature-weighting approach ($\times$10) partially recovers global Rank IC (0.072), but backtest performance remains negative ($-8.5\%$ net). This reveals that the improved global IC reflects inflated time-series variance rather than better cross-sectional discrimination. Artificially forcing FinBERT features into more splits leads the model to overfit idiosyncratic call-level patterns that do not aggregate into stable portfolios.

\subsection{Limitations}

\begin{enumerate}[noitemsep]
    \item \textbf{Cross-model universe comparison}: JKP-only is trained and evaluated on the full CRSP universe ($\approx$122K observations), while FinBERT-containing models use only the freshness-filtered sub-universe ($\approx$104K observations, firms with a call in the past 3 months). This size and composition difference makes direct comparisons across these model groups partially confounded; FinBERT models systematically cover a different --- and likely larger-cap --- universe.
    \item \textbf{Universe coverage}: the freshness filter retains only firms with recent earnings calls --- typically mid- and large-caps. Results may not generalise to small-cap or infrequently covered stocks.
    \item \textbf{Test period}: five years (2019--2023) provides limited statistical power. The Sharpe ratio of 0.79 should be interpreted cautiously: with 60 monthly observations, the standard error on the Sharpe is $\approx 0.13$, leaving meaningful uncertainty around the point estimate. The 108-month rolling IC analysis ($t$-stat 2.67) provides stronger evidence of signal persistence.
    \item \textbf{Freshness cutoff}: the 3-month threshold was set a priori. Sensitivity analysis (Table~\ref{tab:freshness}) shows IC is 3$\times$ higher at 1 month; the optimal cutoff that maximises risk-adjusted backtest performance remains untested.
    \item \textbf{Transaction costs}: 0.2\% one-way is conservative for large-caps but may underestimate costs for smaller firms. Sensitivity analysis (Table~\ref{tab:costs}) shows FinBERT-only remains profitable up to 0.4\% one-way (Sharpe 0.60), suggesting the strategy is robust to realistic cost assumptions.
    \item \textbf{FinBERT context window}: the 512-token limit requires text chunking. Very long Q\&A sections lose information beyond the early chunks.
\end{enumerate}
